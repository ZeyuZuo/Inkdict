# Inkdict dictionary protocol, version 1

Status: **frozen**, 2026-10-27. Later revisions may only add what this version allows to be added, or make an unclear rule explicit; they never change the meaning of an existing type, field or rule. A change in meaning starts version 2.

| File | Contents |
|---|---|
| `v1.md` (this file) | Entry content, the type registry, themes, languages, links, resource references |
| `pack-v1.md` | The source directory, packing, the `.inkdict` file format, the word list |
| `pack-v1.sql` | The `.inkdict` table definitions |
| `samples/en-zh/` | A complete source directory of a small invented dictionary |

The key words "must", "must not", "should" and "may" are used in their usual specification sense.

## 1. Who decides what

| The dictionary pack decides | The application decides |
|---|---|
| Entry content, node types and how they nest | Window layout, the word list, history, dictionary management |
| How an entry looks: markers, numbering, sizes, colours, font roles (the theme) | Light or dark appearance; which installed font fills each font role; base text size and zoom |
| Declared languages, word-list summaries | Display switches (pronunciation, examples), generated from the roles the pack declares |

An application touches entry structure only through the **roles** defined by this protocol (§3.2) and through **`lang`**. It never relies on a dictionary's own type names: type names belong to each dictionary.

## 2. Entry content

An entry is a tree of JSON nodes:

| Key | Meaning |
|---|---|
| `type` | Required. A type name from the type registry |
| `id` | Optional; unique within the entry. Required on the root, where it is the entry **key**: unique in the pack, usually the headword, with a suffix for homographs (`bank-2`) |
| `lang` | A BCP 47 language tag. Required on the root; other nodes inherit their parent's when they omit it |
| `attrs` | Attributes declared for the type in the registry |
| `text` | Plain text; the same as `children: ["…"]`. Must not appear together with `children` |
| `children` | An array of nodes and strings; strings only where the registry allows `#text` |

Empty strings, arrays and objects are left out. Content holds only the source text: brackets, separators and number formats are produced by the theme.

A deep link from outside the pack is `<entry key>#<node id>`.

## 3. Type registry (`types.toml`)

```toml
[meta]
format = "inkdict-types"
version = 1

[groups]
inline = ["#text", "strong", "target"]

[types.pos_group]
kind = "block"                 # block | inline: the layout when the theme says nothing
children = ["head", "sense"]   # allowed child types; #text for strings, @name refers to [groups]
attrs = { n = "int?" }         # string | int | bool | res | ref | enum(a|b); a trailing ? makes it optional
roles = ["anchor"]
index = "headword"             # only for types with the index role: the index kind (§3.1)
doc = "notes for people reading the registry"
```

Type names use only the lowercase letters `a`–`z` and `_`: the names a theme selector can write (§4.1).

A reader that meets a type missing from the registry shows its text inline and does not fail.

### 3.1 Index kinds

Nodes whose type has the `index` role go into the form index (`pack-v1.md` §3). The type's `index` field is one of:

| Kind | Meaning | Shown in the word list as |
|---|---|---|
| `headword` | A headword, including nested ones such as derived words | The word itself |
| `variant` | A variant spelling | The word → the headword it belongs to |
| `inflection` | An inflected form | The word → the headword it belongs to |
| `phrase` | An idiom, phrase or compound | The phrase itself |
| `reading` | A spelling of the pronunciation used for lookup (pinyin, kana) | The headword followed by the reading |
| `hidden` | A form used only to find the entry, never shown itself | The headword it belongs to |

### 3.2 Roles

| Role | What the application does |
|---|---|
| `index` | Puts the node's text into the form index, whether or not it is displayed |
| `anchor` | A node of this type that has an `id` can be the target of a link or of a word-list row. Not every such node needs an `id` |
| `link` | Clickable; followed as in §6 |
| `audio` | Plays the node's first `res` attribute declared in the registry; without that attribute no play control is shown |
| `image` | Shows the node's `res` attribute as a picture |
| `homograph` | The homograph number: its text is a positive integer that the word list shows after the headword (`pack-v1.md` §2.3) |
| `pronunciation` | Hidden or shown by the pronunciation display switch |
| `example` | Hidden or shown by the examples display switch |
| `optional` | When expanding index readings, the node may be left out (`the lower middle classes` gives readings with and without `the`) |
| `choice` | When expanding index readings, one of several adjacent nodes of this kind is taken (`pull` / `drag` gives two readings) |

An application offers a display switch only when the pack declares the matching role.

## 4. Themes (`themes/<name>.toml`)

```toml
[meta]
format = "inkdict-theme"
version = 1
name = "Default"

[fonts.text]                              # a font token: candidate fonts per language
default = ["Source Serif 4", "serif"]
"zh-Hans" = ["Noto Serif CJK SC", "serif"]

[colors.light]  fg = "#1b1c1f"            # colour tokens; light and dark must define the same names
[colors.dark]   fg = "#e5e5e7"

[style."sense > definition"]  display = "inline"
```

For each node, a font token is resolved by the node's `lang`: first an exact tag match, then the primary subtag (`zh-Hans` → `zh`), then `default`.

### 4.1 Selectors

| Syntax | Matches |
|---|---|
| `definition` / `*` | A type / any type |
| `badge[scheme=core]` / `sense[n]` | An attribute with this value / an attribute that is present; booleans are written `true`, `false` |
| `definition[lang=zh]` | A language by subtag prefix, using the inherited `lang` |
| `idiom sense` / `sense > head` | A descendant / a direct child |
| `::before` `::after` `::title` `::marker` `::icon` | Only the generated text, marker or icon |

When several rules match a node, the one with more attribute conditions wins, then the one naming more types, then the one later in the file.

### 4.2 Properties

Text properties (inherited): `font` (a token), `size` (a multiple of the parent's size), `weight` (normal / bold), `style` (normal / italic), `case` (none / upper / lower / small-caps), `decoration` (none / strike / underline), `color` (a token), `baseline` (normal / super / sub), `line_height`.

Box properties (not inherited):

| Property | Meaning |
|---|---|
| `display` | `block`, `inline` or `none`; without it, the type's `kind` |
| `before` / `after` | Text inserted before / after. `{attribute}` inserts a node attribute; when that attribute is missing, the whole text is left out |
| `join` | Text between adjacent siblings of the same type |
| `title` | A heading above the block |
| `marker` | A hanging marker drawn in the space `indent` leaves at the start of the line; may use `{attribute}` |
| `icon` | `none`, `speaker`, `key`, `arrow` or `diamond`; the `audio` role uses it as the play control |
| `hide_text` | Show only the icon and before / after |
| `space_before` `space_after` `space_start` `space_end` `indent` | Spacing in em; start, end and indent follow the writing direction |
| `background` `padding` `radius` | Background colour token, padding, corner radius |
| `divider` | Colour token of a line under the block |
| `collapse` | `none`, `open` or `closed`; the first child is the summary shown when collapsed |
| `max_width` | Maximum width in em, for pictures |
| `tabs` | `true`: adjacent siblings of this kind are drawn as tabs, see §4.4 |
| `tab_label` | A selector that finds the tab's label inside the node, see §4.4 |
| `tab_accent` | Colour token of the selected tab's indicator; without it, the label's colour |

`::` pseudo-elements take only text properties; in addition `::title` may set `space_after` and `::marker` may set `icon`.

### 4.3 Rendering rules

1. White space at the start and end of a line is not shown (as CSS `white-space: normal`).
2. The writing direction follows the script of the node's `lang` (Arabic and Hebrew, for example, are right to left).
3. Theme stack: the pack's theme at the bottom, an optional user theme on top. Rules of the upper layer take precedence over all rules of the lower one; tokens are merged by name.

### 4.4 Tabs

Whether tabs are used, and what the tabs say, is decided by the theme alone.

```toml
[style.pos_group]
tabs = true
tab_label = "head > pos"
tab_accent = "accent"
```

1. Adjacent siblings with `tabs = true` under one parent form one tab group. The tab bar is drawn where the first of them would be; one of them is shown at a time. A group of one node is shown normally, without a tab bar.
2. A tab's label is the text of the first descendant that matches `tab_label`, with that descendant's text properties; the descendant is not shown again inside the tab. Without a match the label is the tab's number (1, 2, 3…).
3. The first tab is shown by default. When the place to open (a link's anchor, a word-list row's anchor) lies inside a tab, that tab is shown.
4. A user theme may set `tabs = false` to turn tabs off; the nodes are then shown one after another as ordinary blocks.

## 5. Languages

A pack declares in its manifest the `source` language (of headwords and original text) and the `targets` (translation languages; empty for a monolingual dictionary). Applications use them only to show a dictionary's languages in dictionary management.

A node's `lang` decides its fonts (§4) and writing direction (§4.3). Applications have no language switch: every language in an entry is shown. To hide a language, use a user theme, for example `[style."definition[lang=zh]"] display = "none"`.

The pronunciation and examples switches change only what is displayed, never the index.

## 6. Links

A node with the `link` role (attributes `entry` and `anchor`) leads to the first of these targets that exists:

1. `entry` is in the pack: open it. When `anchor` is the `id` of a node in that entry, scroll to that node; otherwise stay at the top.
2. `anchor` is the `id` of a node in the current entry: scroll to it.
3. Otherwise: look up the node's whole text.

## 7. Resource references

A `res` attribute holds `kind:key` (for example `audio:harbour-gb`). A reader first looks in the pack's `resources` table, then tries the online templates in `resource_sources` in order (`pack-v1.md` §4).
