Dictionaries from a folder, a choice among a dictionary's themes, and macOS builds that open.

## What is new

- **A dictionary folder.** The app reads every `.inkdict` file in one folder: put a file there and it appears when the app starts or its window is focused again; take it out and it disappears. The settings show the folder, open it in the file manager and can change it. 添加词典… (Add dictionary) copies the file into the folder, and deleting a dictionary moves its file to the trash. Dictionaries added in 0.1 stay in the list.

  | System | Default folder |
  | --- | --- |
  | Linux | `~/.local/share/win.zeyuz.inkdict/dictionaries` |
  | Windows | `%APPDATA%\win.zeyuz.inkdict\dictionaries` |
  | macOS | `~/Library/Application Support/win.zeyuz.inkdict/dictionaries` |

- **Entry styles.** When a dictionary carries several themes, the dictionary menu at the bottom of the sidebar lists them under 词条样式 (in a narrow window, the book button at the top). The choice is remembered for each dictionary.
- **macOS**: one `.dmg` for Apple silicon (`aarch64`) and one for Intel (`x64`), instead of a single universal one. The app is now signed ad hoc, which fixes 0.1.0 being reported as damaged on Apple silicon.
- The fold arrow of collapsible blocks shows in every theme.

## First start on macOS

The app is not notarized by Apple, so macOS stops it the first time. Open it once, then go to System Settings → Privacy & Security and click **Open Anyway**. If macOS still says the app is damaged, run `xattr -dr com.apple.quarantine /Applications/Inkdict.app` in Terminal.

## Known limitations

- The app's interface is in Chinese only; an English interface is planned.
- The Windows and macOS builds are not code-signed with a developer certificate, so the system warns on first start.
- Dictionaries whose audio is Ogg Opus play on macOS 15.4 or later.
- No looking up selected text from other apps yet, and no Android app.
- Inkdict ships no dictionary content apart from the sample. Use dictionaries you have the right to use.
