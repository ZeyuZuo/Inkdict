# 路线图

每个阶段都有退出条件，满足后再进入下一阶段。数据相关的工作（抓取、转换、打包、媒体上传）在各词典的数据仓库里做，不在这里。

## 已定的决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 词典包用 SQLite（`.zdpack`） | 随机读取、前缀检索、FTS5 都是现成的；Android、桌面、浏览器（WASM）、Cloudflare D1 都能读 |
| D2 | 共享 Rust 核心，各端只写界面 | 检索、排序、纠错、主题计算只实现一次，三端结果一致 |
| D3 | Android 用 Kotlin + Compose，经 UniFFI 调用核心 | 原生手感、启动快、能接系统选词菜单 |
| D4 | 桌面用 Tauri 2，复用 Web 前端 | 安装包小（用系统 WebView）；不必为三个桌面系统各写一套界面 |
| D5 | Web 用 TypeScript + 轻量框架（Solid 或 Svelte，开工时定） | 富文本排版用 HTML/CSS 最成熟 |
| D6 | 本仓库不放词典数据 | 词典正文和媒体有版权；协议和软件可以公开 |

## 阶段

### M1 Rust 核心：读包与查词

- [ ] 打开 `.zdpack`，校验标识和版本，读取 meta、类型表、主题、zstd 字典
- [ ] 按 key 取词条并解析
- [ ] 联想：`norm` 与 Python 参考实现逐字一致，排序、去重一致
- [ ] 全文检索：`fts_query` 一致，rowid 解码
- [ ] 资源 URL、锚点编号、链接回退
- [ ] 命令行工具 `zdict`（`suggest`/`search`/`show`），用于手动验证和基准测试

退出条件：对一组固定查询，与 Python 参考读取器的输出完全一致；联想 p95 不高于 Python 版本。

### M2 核心：纠错与渲染树

- [ ] FST + SymSpell 纠错（编辑距离 2 以内）
- [ ] 主题解析与层叠计算（含主题栈，`spec/v0.md` §7.2），输出渲染树
- [ ] 渲染树快照测试（用 `oxdata/` 中的词条，测试数据不入库）

### M3 Web

- [ ] `apps/web`：即时联想、词条渲染、发音、链接跳转、历史、深色模式
- [ ] `server/`：Worker API（`/suggest`、`/search`、`/entry/:key`），数据放 D1
- [ ] 离线模式：浏览器下载包，WASM 核心本地查

退出条件：每天能用它查词；联想服务端 p95 < 50 ms，词条渲染 < 100 ms。

### M4 桌面

- [ ] Tauri 2 包装 `apps/web`，核心在 Rust 侧直接调用
- [ ] 全局快捷键、剪贴板取词、迷你窗口

### M5 Android

- [ ] UniFFI 绑定（`crates/zdict-ffi`），Compose 渲染器
- [ ] 下载正文包；媒体在线播放并缓存，或下载媒体包
- [ ] 系统选词菜单 `PROCESS_TEXT`、分享查词

### M6 协议通用化

- [ ] 接入第二本词典（非英汉），按结果修订为 spec v1
- [ ] 可选：把打包器移植为 `zdict pack`，数据仓库不再依赖 Python
